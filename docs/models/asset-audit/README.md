# 三维游戏资产检查与首轮修复

检查对象为独立三维游戏，优先电脑浏览器。当前保留第三人称、十九组场景、原版小游戏、剧情事件和存档格式。资产检查与模型视觉验收分开记录。

## 当前数据

[模型与场景统计](measurements.json)由项目脚本直接读取清单和二进制模型生成，不依赖旧交付说明。

- 配置二十二个模型文件，合计三亿一千九百九十八万四千八百四十四字节，约三百二十兆字节。
- 牢房配置五个正式模型，共七千三百七十六万七千二百二十八字节，九十六万六千一百零八个三角面。海报和圣经仍为基础几何。
- 图书馆五次摆放书架，配置模型的实例面数为二百零一万八千二百五十四；重复文件只下载一次，重复实例仍需参与绘制。
- 床与椅子的文件摘要与资产仓库中的本地建模版一致，不能再把当前版本误认为原始生成稿。
- 牢房主体只有一份材质，两张二千零四十八像素方形贴图，没有法线贴图引用；应优先拆分建筑和改善贴图密度。

上述面数包括配置的剧情隐藏物件，不包含程序基础几何及主角，不是每帧实测数据。文件体积不是显存占用。尺寸统计为游戏坐标单位，不能将十三乘十三布局直接称为现实米数。

## 已完成修复

共用模型加载函数现在为导入模型的所有嵌套网格开启投射和接收阴影。之前只有程序基础几何开启阴影，正式建筑替换后人物与家具无法在地面形成正确投影。修复仅修改每个模型副本，不改变缓存源场景、材质、剧情或碰撞。

实际浏览器中已看到人物投影、床腿和墙体投影。近看墙地贴图仍模糊，整体风格和最终灯光尚未通过美术验收；阴影功能修复不等于资产精修完成。开启阴影会增加渲染工作，后续应结合目标设备帧时间决定静态建筑烘焙与动态物体阴影范围。

## 复现

在独立三维应用目录运行：

```sh
npm run audit:assets
npm test
npm run build
```

中文说明：重新检查全部已配置模型，运行回归测试，然后构建可发布文件。检查脚本只读取模型并更新统计报告，不修改模型或访问生成服务；传入文件路径可以另存检查结果。

统计包含默认场景节点变换、重复实例、图元数、材质引用、内嵌贴图信息、动画名称和文件摘要。贴图尺寸仅直接解析内嵌的便携式网络图形格式，其他格式保留未知值。静态边界不包含骨骼和动画变形。

## 验证结果

- 三十六项测试通过，包括模型副本阴影、缓存复用、失败重试、失效场景、损坏模型检测、所有场景入口可达和二百五十六种剧情状态组合。
- 生产构建成功；现有主代码包超过构建工具默认提示阈值，该提示不属于本次新增错误，也尚未做代码分包优化。
- 浏览器验证了牢房环境查看、恢复剧情、走到后墙、打开原有交互、返回探索；检查时浏览器错误和警告日志为空。未将此记录当作完整人工通关或帧率基准。

## 下一批优先级

先制作牢房模块化墙地和真实洞口；复用本地床椅，精修床品；为书桌和石锤制作运行版本；为海报和旧书制作可控交互。旧书现有结构文件包含动画，接入前应改为剧情驱动播放，不能直接使用加载器默认循环播放第一段动画的行为。

其他场景的模型清单保持不变。办公室、管网、雨夜等使用基础几何，不等于运行时缺失文件；后续应按剧情优先级补正式资产。
