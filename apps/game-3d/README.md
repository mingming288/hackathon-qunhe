# 高墙之外 · 第三人称三维剧情贯通版

采用同一仓库内的独立三维应用，原二维游戏及其存档保持独立。
先用基础模型贯通故事，再逐件替换正式模型。当前重点是剧情顺序、任务前置、备用路线与结局可达；精细美术、动作与原版小游戏的完整机制仍待后续制作。

## 当前可用内容

- 十九组可进入的三维基础场景，包括序章、监狱、逃离路线及三个结局的空间。
- 可见的第三人称主角，跟随镜头、拖动环顾、缩放和镜头避墙。
- “开始新游戏／继续游戏”按任务和道具条件解锁通路，显示当前目标、方向、随身物品及线索数量。
- 标准准备路线、石锤被没收后的备用路线、五份直接线索和两份旁听记录，连接三个结局。
- “场景总览”随时查看任意地点及资产清单，返回游戏后恢复原任务与位置。
- 剧情与场景查看分别保存；重新开始会备份上一份三维游戏记录，不读写原二维游戏存档。
- 通过本地模型清单替换基础资产，加载失败保留基础模型。

基础人物的走路摆动由程序驱动，只用于空间测试，不冒充已完成的正式角色骨骼或动作。
当前没有新增云端生成任务或消耗生成积分。

## 启动与验证

在本目录执行：

```sh
npm install
npm run dev
```

中文说明：安装锁定的依赖，然后启动本地开发服务。
默认地址为本机的八〇八一端口；端口占用时直接报错，不自动切换到其他服务。

```sh
npm test
npm run build
```

中文说明：运行剧情、分支、存档隔离和场景基础检查，再生成静态发布文件。

方向键移动，拖动场景转动镜头，滚轮缩放，空格或点击提示按钮交互。
触屏提供方向按钮与拖动镜头，但目前主要验收电脑浏览器，未验证全部移动设备。

## 这一轮怎样贯通故事

剧情参考仓库中的原游戏主脚本和结局脚本，以独立任务事件组织，避免把旧版全局状态直接复制到三维场景里。

1. 电视开场、大门异常、陌生手术室、牢房醒来，衔接进入高墙内的生活。
2. 与瑞德交谈、修收音机取得石锤、帮老布整理图书、领取圣经、藏锤通过检查。
3. 获取海报、开始挖掘、分次倒土、经历岁月流逝，再整理管网地图。
4. 进入办公室、藏身、找到保险柜、调包账本，返回通道完成挖掘。
5. 借雷声砸管、穿过地下管网、到达雨夜出口，再进入对应结局。

没有藏好石锤就接受检查，会进入训诫、禁闭、听取老布建议、办公室搜查和找回工具的备用路线；之后重新汇入逃离主线。

| 结局 | 进入条件 | 可游玩顺序 |
|---|---|---|
| 相逢的海滩 | 已取得瑞德线索，且未满足调查结局条件 | 瑞德寻找橡树、开盒读信、乘车赴约、海边重逢 |
| 高墙下的名单 | 五份直接线索，或至少四份直接线索与两份旁听记录 | 核对证据、寄信、调查医疗机构、补全记录、抓捕、结语 |
| 形同陌路 | 不满足以上条件 | 安迪银行取款、沿海驾车、修船；切换瑞德完成超市工作与自主决定 |

调查结局优先判定。普通的“与瑞德交谈”任务不自动取得其线索，需要主动选择追问。角色在对应结局阶段切换，始终使用第三人称镜头。

收音机、图书排序、藏锤、画地图、雷声砸管及超市装袋，目前采用简化交互面板承载相同的任务节点。驾驶、押送、时间流逝通过叙事转场连接；未实现完整驾驶、潜行、管道爬行动作或原版小游戏机制。

本轮检查聚焦任务能否继续、各分支能否结束、保存能否恢复、查看场景是否影响剧情。碰撞尺寸、镜头遮挡、动作和正式模型尺度留到资产接入后统一打磨。

## 逐步替换正式模型

把文件放进应用的公开资产目录，再编辑模型清单。

- 文件目录：
  `public/assets/models/`
- 模型清单：
  `public/assets/models.json`

清单示例（示例文件不随基础版提供，获得真实模型后再填写）：

```json
{
  "version": 1,
  "models": {
    "red": { "url": "/assets/models/red.glb", "height": 2.5 },
    "bed": { "url": "/assets/models/bed.glb", "height": 1.2 }
  }
}
```

中文字段说明：版本、模型映射、文件地址与目标高度。
使用 GLB（二进制三维模型）格式，文件地址限定当前应用的模型目录，不能填入密钥或临时签名地址。
普通道具按目标高度缩放，脚底归零；可选朝向字段使用弧度。
带骨骼的模型使用保留骨架的复制方式；若文件含动画，基础预览播放实际存在的第一个片段。
待机、行走、持物等动作与任务的切换，属于后续角色控制接入工作。

每个场景还提供“场景标识加建筑后缀”的整体建筑替换位，例如：

```json
{
  "cell-architecture": {
    "url": "/assets/models/cell-shell.glb",
    "normalize": false
  }
}
```

中文字段说明：牢房建筑槽位、模型地址、关闭尺寸归一化。
整体建筑必须使用与基础版相同的米制尺寸、中心原点、地面高度和门洞位置。
建筑替换只更新外观，不自动移动碰撞、人物站位或出入口；这些应在场景验收中同步核对。

当前可复用资产标识包括：床、桌椅、书架、收音机、海报、保险柜、人物、车辆与树木。
具体英文标识集中在场景数据和几何套件中，它们是代码连接键，不是界面文字。

## 文件职责与三人协作

| 文件 | 职责 | 建议主要负责人 |
|---|---|---|
| src/scenes.js | 场景标识、陈设、出入口与旧版映射 | 场景负责人 |
| src/world.js / src/kit.js | 基础建筑与道具几何 | 场景负责人 |
| src/controller.js / src/movement.js | 第三人称控制、镜头和移动碰撞 | 场景负责人 |
| src/actor.js / src/assets.js / public/assets | 临时角色与正式模型替换 | 人物资产负责人 |
| src/story-data.js / src/story.js | 任务数据、前置条件、道具、分支和结局判定 | 剧情负责人 |
| src/routes.js / src/navigation.js | 当前任务的下一段通路、返回入口落点 | 场景负责人 |
| src/save.js | 剧情事件重放、独立查看记录、重新开始备份 | 集成负责人 |
| src/dialogue.js | 对话和简化任务交互 | 剧情负责人 |
| src/world-view.js | 三维显示、人物切换、目标标记和交互选择 | 场景负责人 |
| src/main.js | 菜单、剧情模式与场景查看模式的连接 | 集成负责人 |
| tests/story.test.js / tests/scenes.test.js | 分支贯通、存档隔离与场景基础检查 | 集成负责人 |

场景只描述空间与资产，剧情通过稳定的任务和资产标识连接；替换模型时不必重写任务流程。
当前碰撞限定平地与矩形障碍；多层建筑、楼梯、复杂动态门和完整管道爬行需要后续扩展。
场景查看的说明弹窗与正式剧情对话分开，不会触发任务。后续可逐步扩充对白、演出和任务机制，不改变已有存档中的事件标识。
