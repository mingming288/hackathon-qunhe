# 高墙之外 · 第三人称三维场景基础版

采用同一仓库内的独立三维应用，原二维游戏及其存档保持独立。
先搭建全部空间，再逐件替换正式模型；当前交付为场景预览，不是已迁移全部任务的完整游戏。

## 当前可用内容

- 十九组可进入的三维基础场景，包括序章、监狱、逃离路线及三个结局的演出空间。
- 可见的第三人称主角，跟随镜头、拖动环顾、缩放和镜头避墙。
- 平地移动、角色与矩形障碍碰撞、沿墙滑动、短距离场景出入口交互。
- 场景总览可直接选择任意地点；底部明确提示原任务尚待迁移。
- 独立保存上次场景和安全位置，不读写原游戏的任务存档。
- 通过本地模型清单替换基础资产，加载失败保留基础模型。

基础人物的走路摆动由程序驱动，只用于空间测试，不冒充已完成的正式角色骨骼或动作。
当前没有新增云端生成任务或消耗生成积分。

## 启动与验证

在本目录执行：

```sh
npm install
npm run dev
```

中文说明：安装锁定的依赖，然后启动本地开发服务。
默认地址为本机的八〇八一端口；端口占用时直接报错，不自动切换到其他服务。

```sh
npm test
npm run build
```

中文说明：运行场景与移动检查，再生成静态发布文件。

方向键移动，拖动场景转动镜头，滚轮缩放，空格或点击提示按钮交互。
触屏提供方向按钮与拖动镜头，但目前主要验收电脑浏览器，未验证全部移动设备。

## 逐步替换正式模型

把文件放进应用的公开资产目录，再编辑模型清单。

- 文件目录：
  `public/assets/models/`
- 模型清单：
  `public/assets/models.json`

清单示例（示例文件不随基础版提供，获得真实模型后再填写）：

```json
{
  "version": 1,
  "models": {
    "red": { "url": "/assets/models/red.glb", "height": 2.5 },
    "bed": { "url": "/assets/models/bed.glb", "height": 1.2 }
  }
}
```

中文字段说明：版本、模型映射、文件地址与目标高度。
使用 GLB（二进制三维模型）格式，文件地址限定当前应用的模型目录，不能填入密钥或临时签名地址。
普通道具按目标高度缩放，脚底归零；可选朝向字段使用弧度。
带骨骼的模型使用保留骨架的复制方式；若文件含动画，基础预览播放实际存在的第一个片段。
待机、行走、持物等动作与任务的切换，属于后续角色控制接入工作。

每个场景还提供“场景标识加建筑后缀”的整体建筑替换位，例如：

```json
{
  "cell-architecture": {
    "url": "/assets/models/cell-shell.glb",
    "normalize": false
  }
}
```

中文字段说明：牢房建筑槽位、模型地址、关闭尺寸归一化。
整体建筑必须使用与基础版相同的米制尺寸、中心原点、地面高度和门洞位置。
建筑替换只更新外观，不自动移动碰撞、人物站位或出入口；这些应在场景验收中同步核对。

当前可复用资产标识包括：床、桌椅、书架、收音机、海报、保险柜、人物、车辆与树木。
具体英文标识集中在场景数据和几何套件中，它们是代码连接键，不是界面文字。

## 文件职责与三人协作

| 文件 | 职责 | 建议主要负责人 |
|---|---|---|
| src/scenes.js | 场景标识、陈设、出入口与旧版映射 | 场景负责人 |
| src/world.js / src/kit.js | 基础建筑与道具几何 | 场景负责人 |
| src/controller.js / src/movement.js | 第三人称控制、镜头和移动碰撞 | 场景负责人 |
| src/actor.js / src/assets.js / public/assets | 临时角色与正式模型替换 | 人物资产负责人 |
| src/main.js | 应用入口、场景切换与界面连接 | 集成负责人 |
| tests/scenes.test.js | 可达性、碰撞与模型清单检查 | 集成负责人 |

后续剧情任务应通过独立模块接入，避免在场景数据里重新混入完整业务流程。
当前碰撞限定平地与矩形障碍；多层建筑、楼梯、复杂动态门和完整管道爬行需要后续扩展。
场景观察弹窗只说明预览状态，不替代原游戏的真实人物对白。
