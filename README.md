# 入戏

一款在浏览器中游玩的第三人称三维剧情冒险游戏。玩家走进监狱、与人物交谈、收集道具和线索，在漫长准备与风险选择中走向不同结局。

**[立即试玩《入戏》](https://hackathon-qunhe.vercel.app/)**

建议先使用电脑浏览器体验。模型按场景加载，首次进入或切换场景时需要下载资源；存档保存在当前浏览器中，不会自动同步到其他设备。

## 当前版本

- 十九组三维场景，包含客厅序章、牢房、走廊、院子、图书馆、办公室、挖掘通道、地下管网、雨夜及结局场景。
- 第三人称移动、镜头环顾与缩放、碰撞和避墙，以及场景之间的过门衔接。
- 俯视导航地图、可点击地标、按需指路、自动行走和右侧任务提示。
- 已接入正式人物模型、部分人物的待机与行走动画，以及非玩家角色巡逻。
- 石锤、圣经、收音机、海报、保险柜等道具与互动，包含领取物品展示和剧情线索回看。
- 主线、备用路线与三种结局；修理收音机、整理图书、藏锤、挖掘、倒土、管道地图和雷声砸管等互动。
- 开始新游戏、继续游戏及独立的场景总览；原二维游戏与三维版分别保存进度。

当前版本仍在迭代：部分人物复用模型，狱警模型尚无骨骼动画；碰撞采用简化几何，不等同于模型表面的逐三角面碰撞。触屏已有基础控制，但尚未验证全部移动设备的体验。

## 操作方式

| 操作 | 方式 |
|---|---|
| 移动 | 方向键，或键盘左侧的四个方向字母键 |
| 加速移动 | 按住换挡键并移动 |
| 环顾、调整镜头 | 拖动鼠标；滚轮缩放；“重置镜头”恢复视角 |
| 交谈、调查、领取道具 | 靠近目标后按空格，或点击交互提示 |
| 查看地图 | 点击地图栏，或按地图切换键 |
| 自动指路 | 点击地标或“为我指路”；手动移动可取消自动行走 |
| 查看已有线索 | 展开“物品与操作”，点击“查看线索记录” |
| 浏览场景 | 点击“场景总览”，可返回原游戏进度 |

```text
W / A / S / D    Shift    M
```

中文说明：依次为前、左、后、右移动键，换挡加速键，以及地图展开或收起键。小游戏内部操作以画面提示为准。

## 本地启动

运行环境使用 Node.js 22.12 或更高版本。

中文说明：这是安装依赖和构建网页所需的运行环境；玩家在线试玩不需要安装。

```bash
git clone https://github.com/mingming288/hackathon-qunhe.git
cd hackathon-qunhe
npm ci --prefix apps/game-3d
npm run dev --prefix apps/game-3d
```

中文说明：克隆原仓库、进入项目，按锁文件安装三维应用依赖，然后启动本地开发服务。也可以克隆下方列出的个人派生仓库，后续命令相同。

[打开本地游戏](http://127.0.0.1:8081/)。默认端口为 8081，端口占用时会报错。

**三维版需要通过开发服务或构建后的静态站点运行，不要直接双击源码首页文件。** 构建时会读取同一仓库内原二维项目的代码与素材，必须保留完整仓库目录关系。

## 验证与构建

在仓库根目录执行：

```bash
npm test --prefix apps/game-3d
npm run build --prefix apps/game-3d
npm run preview --prefix apps/game-3d
```

中文说明：依次运行现有自动化测试、生成静态发布文件、启动本地发布预览服务。自动化测试不能替代完整的人工试玩和目标设备性能验证。

构建输出位于：

```text
apps/game-3d/dist/
```

中文说明：三维游戏的静态发布目录，包含网页、脚本、音效和模型资源。运行时无需另行搭建业务服务器或数据库。

## 仓库结构与三维资源

| 目录 | 内容 |
|---|---|
| `apps/game-3d/`<br>中文说明：三维应用目录 | 当前《入戏》的页面、源码、测试与构建配置 |
| `apps/game-3d/public/assets/models/`<br>中文说明：游戏模型目录 | 人物、场景、家具、道具及独立动画文件 |
| `apps/game-3d/public/assets/models.json`<br>中文说明：模型配置清单 | 将游戏对象与模型资源连接，指定比例、朝向和动画 |
| `apps/game-3d/scripts/`<br>中文说明：资产处理脚本目录 | 场景建模、资源优化与资产检查脚本 |
| `Beyond the wall/`<br>中文说明：原二维游戏目录 | 原版代码、素材及被三维版复用的互动内容 |
| `docs/models/`<br>中文说明：模型文档目录 | 建模说明、资源盘点与阶段性验证记录 |
| `README/docs/readme/`<br>中文说明：原版展示图片目录 | 原二维游戏的封面和展示图片 |

模型以二进制三维资源格式保存在仓库内，部分文件内含贴图与动画。资源清单不是目录中的全部文件：仓库也保留了一些旧版、原始版和优化前的模型；发布包大小不代表玩家每次打开页面都会下载全部模型。

[三维应用开发记录](apps/game-3d/README.md) · [资产检查说明](docs/models/asset-audit/README.md)

开发记录包含历史阶段说明，当前已实现内容以代码及本文“当前版本”为准。

## 两个仓库如何同步与上线

| 仓库 | 用途 |
|---|---|
| [原仓库](https://github.com/mingming288/hackathon-qunhe) | 汇总开发与集成修改 |
| [个人派生仓库](https://github.com/xiaolishengqile/hackathon-qunhe) | 当前线上网站连接的代码来源 |

```text
codex/third-person-scenes → main → 派生仓库 main → 自动构建与发布
```

中文说明：场景开发分支完成验证后合入原仓库主分支，再把同一个已验证提交同步到个人派生仓库主分支；部署平台监听个人派生仓库的主分支并自动发布。

**派生仓库不会自动跟随原仓库更新。** 只推送原仓库开发分支，或只更新原仓库主分支，都不等于线上网站已更新。发布时需要：

1. 提交本次要发布的改动，保留不属于本次发布的未完成工作。
2. 拉取并合并远程更新，处理冲突，完成测试和构建。
3. 将已验证内容合入主分支；有写入权限时，把同一提交普通推送到两个仓库的主分支。
4. 若任一仓库出现分叉，先合并并重新验证，不使用强制推送覆盖他人提交。
5. 检查部署平台显示的源仓库、主分支提交和发布状态，再确认正式网址上的页面与模型清单。

当前托管平台为 Vercel。

中文说明：负责从个人派生仓库自动构建并发布静态网站的托管服务。

如重新配置部署，可以将项目根目录设为整个仓库，安装命令与构建命令沿用上文，输出目录设为三维应用的构建输出。这样原二维项目的构建依赖也能被读取。无论采用哪种目录配置，都应验证原版代码和素材能参与构建。
